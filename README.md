# Concrete Strength Prediction

A regression project predicting concrete compressive strength from mix
design (cement, water, aggregates, admixtures) and curing age, with a focus
on domain-informed feature engineering and model interpretation over raw
model complexity.

The dataset (`data/concrete_mixes.csv`) is synthetically generated by
`scripts/generate_dataset.py` (fixed seed, 1,030 samples) rather than a
redistributed public dataset. Strength is simulated from established
concrete-engineering relationships — Abrams' law (water/binder ratio),
logarithmic strength gain with curing age, delayed pozzolanic contribution
from fly ash/slag, and lab-realistic noise — so the patterns a model finds
here are the same ones that show up in real mix-design data. Clone the repo
and run the generator to rebuild everything from scratch.

#### Target distribution

![strength distribution](output/01_strength_distribution.png)

Compressive strength ranges roughly 2-85 MPa with a mean around 44 MPa,
consistent with a mix spanning low-strength to high-performance concrete.

#### Feature correlations

![correlation heatmap](output/02_correlation_heatmap.png)

Beyond the raw mix quantities, the correlation matrix includes engineered
features: **binder** (total cementitious material = cement + slag + fly
ash), **water/binder ratio**, **water/cement ratio**, **SCM fraction**
(share of binder that's slag/fly ash rather than cement), **aggregate
ratio**, and **log(age)**. The water/binder ratio and log(age) show by far
the strongest correlation with strength — raw water and raw cement alone
are noticeably weaker predictors, which is the main justification for
engineering the ratio features rather than feeding the model raw quantities.

#### Water/binder ratio: the dominant relationship

![wc ratio](output/03_wc_ratio_vs_strength.png)

This reproduces Abrams' law directly in the data: strength falls off
sharply as the water/binder ratio rises, and the effect is consistent
across curing ages (colour). Mixes above a ~0.6 ratio essentially never
reach high strength regardless of how long they cure.

#### Strength gain with curing age

![age vs strength](output/04_age_vs_strength.png)

Strength climbs quickly in the first 28 days and then levels off — most of
the gain is realized by day 28, with only modest further improvement out to
365 days. This matches the diminishing-returns curing behavior used to
generate the data and is a useful sanity check that the simulation is
behaving physically.

#### Model: Gradient Boosting Regressor on engineered features

Rather than comparing many models, this project deliberately focuses on
getting the **feature set right** and then fitting one strong, well-tuned
model (`GradientBoostingRegressor`, 400 shallow trees) on top of it, with
full interpretation of what it learned.

![actual vs predicted](output/05_actual_vs_predicted.png)

On a held-out 20% test split: **R² ≈ 0.97, MAE ≈ 2.4 MPa, RMSE ≈ 3.1 MPa**
(5-fold cross-validated R² ≈ 0.966 ± 0.003, so the fit isn't a lucky split).
Full numbers in `output/model_report.txt`.

![residuals](output/06_residuals.png)

Residuals are centered near zero with no obvious funnel shape against
predicted values, and the residual distribution is roughly symmetric —
there's no strong sign the model is systematically biased at the low or
high end of the strength range.

#### What does the model actually rely on?

![feature importance](output/07_feature_importance.png)

Permutation importance (shuffle each feature, measure the drop in R²) shows
**age (both raw and log-transformed) and water/binder ratio dominate**,
consistent with the two engineering relationships used to generate the
data in the first place — the model recovered the underlying physics
without being told the rules directly. Raw cement and binder mass matter
far less once the ratio features are available, which is the practical
argument for engineering those features rather than relying on a black-box
model to infer the ratio on its own.

### Possible extensions

- Swap in a real dataset (e.g. the UCI/Yeh concrete compressive strength
  dataset) using the same column names — `generate_dataset.py`'s schema was
  chosen to make that swap close to a drop-in replacement.
- Add SHAP values for per-prediction explanations instead of only global
  permutation importance.
- Wrap the trained model in a small Flask/FastAPI endpoint or Streamlit app
  for interactive "enter a mix design, get a strength estimate" use.

### Project structure

```
concrete_strength_project/
├── data/
│   └── concrete_mixes.csv     # generated dataset (1,030 mix designs)
├── scripts/
│   ├── generate_dataset.py    # builds data/concrete_mixes.csv
│   └── analysis.py            # feature engineering, model, all charts
├── output/                    # all generated charts + model report
└── README.md
```

### How to run

```bash
pip install -r requirements.txt
python scripts/generate_dataset.py   # rebuilds data/concrete_mixes.csv
python scripts/analysis.py           # rebuilds every chart + model_report.txt
```

Built and tested with Python 3.12, pandas, numpy, matplotlib, seaborn, and
scikit-learn (see `requirements.txt`).
